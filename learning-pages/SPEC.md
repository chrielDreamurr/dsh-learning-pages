# SPEC —— 交互式学习页的内容规范

> 这份文件是**写作规范**，不是给人读的教程。它规定了「一个学习页面应该长什么样」，
> 目的只有一个：**用户只要给出主题或素材，就能产出一份风格统一、质量达标的页面，
> 而不需要反复交代细节。**
>
> 引擎、构建、校验都在 `learning-pages/` 下；这里只管**写什么**。

---

## 0. 三十秒上手

```powershell
# 新建（工作区根目录下会多一个文件夹）
node learning-pages/tools/new.js <目录名> --brand "大标题" --subtitle "副标题"

# 编辑 <目录名>/content.js    ← 你唯一要写的文件
# 构建 + 校验
node learning-pages/tools/build.js    <目录名>
node learning-pages/tools/validate.js <目录名>

# 打开
Start-Process <目录名>\index.html
```

**产物**是一个自包含的 `index.html`（约 150~200 KB，零外部依赖，可离线、可单独发给别人）。
`content.js` 是唯一的真相来源；`index.html` 随时可以重新生成，不要手改它。

---

## 1. 文件结构

```
content.js          ← 内容源（唯一要写的文件）
index.html          ← 构建产物（自动生成，勿手改）
source/             ← 选填：素材与验证脚本的归档
```

`source/` 用来放**来源和证据**，让内容里的事实可追溯：

- 从 PDF / 文档提取出来的原文（提取一次就存下来，别每次都重新提）
- 为验证某个判定条件 / 数字而写的一次性程序
  （实例：某道「矩形能否被更小的矩形铺满」的题目，判定条件是四个条件的组合。
   当时写了一个精确覆盖的暴力铺砖程序，在 W,H ≤ 17 的范围内对拍 2197 组、
   零不一致，才敢把那个条件写进正文。这类证据就该留在 `source/` 里。）

它不参与构建，也不会被校验器读到。**但只要内容里有「我算过/我验过」的断言，就把它放进来。**

`content.js` 的形状：

```js
window.PAGE = {
  meta: { brand, subtitle, docTitle, storageKey, extraCss? },
  steps: [ /* 若干节 */ ]
};
```

### 1.1 meta 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `brand` | ✔ | 侧栏顶部大标题。短，就是这份材料的名字 |
| `subtitle` | ✔ | 侧栏标题下的小字。一句话说明定位，如「零基础版 · 36 节」 |
| `docTitle` | ✔ | 浏览器标签页标题。通常 `brand + ' · 学习指南'` |
| `storageKey` | ✔ | 本地进度存档键。**内容大改（增删节、调整选项顺序）后要把版本号 +1**，否则读者旧的答题记录会错位到别的选项上 |
| `extraCss` | ✘ | 页面级额外 CSS 字符串。极少用；只有确实需要改版式时才加 |

## 2. 每一节的数据结构

```js
{
  id:   'c1-2',                    // 必填，全局唯一，字母数字-_，章节前缀命名
  ch:   '第 1 章 · 编程大白话',      // 必填，相同 ch 且相邻 = 侧栏同一分组
  title:'变量：贴了标签的盒子',       // 必填，侧栏与正文标题共用
  tag:  'L2',                      // 选填，标题右侧的小徽章（难度/题号等）
  body: `HTML 字符串`,              // 必填，正文
  q:    { … }                      // 选填；强烈建议每节都有
}
```

### 2.1 题目对象 `q`

```js
q: {
  type: 'quiz' | 'survey',
  text: '题面（一句话，具体，可回答）',
  opts: [
    { label:'选项标题', desc:'副标题（灰字，可省）',
      correct:true,                  // 仅 quiz 用，且必须恰好一项为 true
      why:'选了之后展开的解释',
      next:'c3-1' }                  // 选填：选它并点继续时跳到这一节
  ],
  summary: '答题后显示的那句总结',
  keepOrder: false                   // 选填：true = 这一题不打乱选项（见 §4.4）
}
```

**`quiz` 与 `survey` 的分工：**

| | `quiz` | `survey` |
|---|---|---|
| 有无对错 | 有，恰好一个 `correct:true` | 无 |
| 用途 | 检验理解、纠正误解 | **分诊**（你是什么情况→跳到哪一节）、自我确认、收尾 |
| `why` | **每一项都必须有** | 可省 |
| 选项顺序 | 引擎自动打乱 | **保持原样**（顺序本身有含义） |
| 计入成绩 | 是 | 否 |

### 2.2 分支跳转 `next`

放在选项里，读者选中后点「继续」就会跳到 `next` 指定的 `id`。

- 用来做**分诊**：第 0 章问「你现在什么水平 / 板子到了没有 / 遇到什么现象」，每条路线跳向不同起点。
- 每一章的收尾也可以做**故障分诊**：「切档位会跳变 → 回到讲相位累加器的那一节」。
- `next` 指向的 id 必须真实存在，否则构建时会报错。
- 用 `id` 引用，不要用序号——插入新节时不会失效。

## 3. 章节组织（骨架模板）

一个成熟的学习页面几乎总是这个形状，照抄即可：

| 章节 | 内容 | 为什么必须有 |
|---|---|---|
| **第 0 章 · 开始之前** | ① 这份材料是什么、给谁看 ② 专业黑话先集中翻译一遍 ③ 这个页面怎么用（快捷键） ④ **一道分诊 survey 题** | 零基础读者最需要的是「我知道我在学什么」和「我知道从哪开始」 |
| **概念章（若干）** | 把主题拆成 4~6 个底层概念，每个一节 | 先补齐地基，后面的正课才不会被术语卡住 |
| **正课章（若干）** | 每个知识点 / 每道题 / 每个功能一节 | 主体 |
| **收尾章** | ① **术语速查表**（全篇术语集中翻译） ② 动手任务清单 ③ 下一步路线 | 速查表是这份材料最常被回访的部分 |

**章节名要带序号**（`第 3 章 · L1 八道题`），因为它会出现在侧栏分组、正文面包屑和顶部进度条里。

**每章内部，节与节的 `ch` 必须连续出现**——同一个 `ch` 中间插了别的章节，侧栏就会出现两个同名分组。校验器会报错。

## 4. 写作规范（最重要的一节）

### 4.1 永远站在零基础读者的位置上

- **每个专业名词第一次出现，必须就地解释**，放进青色术语卡。不要假设读者知道任何缩写。
- **先讲「为什么需要它」，再讲「它是什么」，最后才是「怎么做」。** 直接讲怎么做，零基础读者会不知道自己在记什么。
- **用生活里的东西打比方**，而且最好是读者每天都会碰到的东西：
  - 并查集 → 「认老大，同一个老大就是同一个圈子」
  - 按位与 → 「两排开关串在一起，都开着灯才亮」
  - 动态规划 → 「把大问题拆成小问题，把答案记下来别重算」
  - 中断 → 「你在写作业，手机响了，接完电话回来接着写」
  - 置换的循环 → 「拿纸画圈：1→2→3→1」
- **解释一个术语时，不要用另一个术语**。如果非用不可，先把那个也解释了。
- 不要写「众所周知」「显然」「简单来说」——对零基础读者来说没有什么是显然的。真要简化，就直接给简化后的说法。

### 4.2 卡片系统（只有这五种）

| 卡片 | 类名 | 用来放什么 | 频率 |
|---|---|---|---|
| 术语卡 | `c-term` | 解释一个专业词：**比喻 + 一句话定义** | 每节 0~2 个，全篇最常用的卡片 |
| 划重点 | `c-key` | 本节最核心的那句话 | **每节最多 1 个**，多了就不叫重点 |
| 小心坑 | `c-warn` | 新手最容易翻车的地方：**现象 + 原因 + 怎么避免** | 有坑就写，没坑不硬凑 |
| 小技巧 | `c-tip` | 能省时间或提高正确率的经验 | 同上 |
| 动手任务 | `c-task` | 「看完之后具体去做什么」 | 放在章节收尾 |

卡片是**视觉锚点**，不是装饰。一节里如果五种卡片各来三个，读者就什么都记不住了。

术语速查表用 `c-term` 里嵌 `.term` 网格：

```html
<div class="callout c-term"><span class="lb">术语速查表</span>
<div class="term">
  <b>术语一</b><span>一句话解释。</span>
  <b>术语二</b><span>一句话解释。</span>
</div></div>
```

### 4.3 正课的固定讲法

知识点 / 题目类的一节，按这个顺序组织：

1. **一句话大意** —— 用一个生活化的说法讲清楚「这件事到底要做什么」
2. **为什么需要它 / 它在整个体系里的位置**
3. **怎么做** —— 分步骤，必要时配骨架代码
4. **样例/例子走查** —— 用具体数字一步步算给读者看（表格最好）
5. **小心坑 / 小技巧**
6. **一道 quiz** —— 检验刚才那一节最容易被误解的点

**样例走查是效果最好的一招**：不要只说「结果正确」，要把中间每一步都列在表格里，让读者能自己跟着算一遍。

### 4.4 出题规范

这是质量差距最大的地方，逐条照做：

1. **错误选项必须是真实存在的误解**，是读者第一直觉会选的那个。**不要放一眼就能排除的凑数选项**——那等于浪费一次教学机会。
2. **`why` 要解释「哪里想错了」，不是重复正确答案。** 正确项的 `why` 讲透（2~4 句），错误项的 `why` 指出它错在哪个具体点上（1~2 句）。
3. **题面要具体、可回答。** 好：「`7 / 2` 的结果是多少？」；坏：「你理解整数除法了吗？」
4. **不要考记忆，要考理解。** 好：「为什么这样写会出错？」；坏：「刚才那个函数叫什么名字？」
5. 选项 2~9 个（超过 9 个数字键快捷键失效），常用 4 个。
6. `summary` 是答题后的收口，把这道题要传达的那**一条**认知单独拎出来，一句话。
7. **不用管正确答案在第几项** —— 引擎会按节的 id 做确定性打乱，同一份内容每次构建的顺序完全一致。
   只有在选项本身有自然顺序（如「由小到大」）时才写 `keepOrder:true`。

### 4.5 HTML 纪律

- 能用 `<b>` 就别用 `<i>` / `<u>` / `<font>`（主题只定义了 `b/strong` 的高亮色）。校验器会拦禁用标签。
- **`<pre>` 代码块里的 `<` `>` 必须写成 `&lt;` `&gt;`**，否则会被浏览器当成标签吃掉。
- 标签必须配对。校验器会逐节检查 `div/span/p/table/ul/li/b/code` 的开合平衡——**这个检查抓出过真实缺陷，别绕过它**。
- 代码块用 `<pre><code>`，可以用 `<span class="cm">注释</span>`、`.kw` 关键字、`.ok` 正确、`.no` 错误、`.hl` 高亮。
- 表格用 `<table>`；表头 `<th>` 里可以写 `style="width:130px"` 控制列宽。
- 正文里的变量、命令、文件名用 `<code>` 包起来。

### 4.6 事实纪律

这条比文风重要得多：

- **任何数字、样例、判定条件，都要自己算过或跑过。** 涉及计算的，写个小程序验证；涉及多组样例的，逐组核对。
- **原始素材里有错时，不要跟着抄，也不要装作没看见** —— 明确指出「原文这里写错了，正确的是……」，并说明依据（比如「以样例为准」）。读者会因此更信任这份材料。
- **推导不出结论时，如实说「这一步需要自己补齐 / 建议写暴力程序对拍验证」，不要编一个看起来合理的答案。**
  - 实例：某道题的最优复杂度实现有争议，页面里就只给核心思路 + 一个能过部分分的写法，并标注「满分实现需要想清楚 X」，而不是硬编。
- 引用外部资料时给出处。

### 4.7 语言

- 简体中文，第二人称「你」。
- 语气：**鼓励但不油腻**。可以写「答错才是学习的时刻」，不要写「加油哦你一定可以的～」。
- 少用「首先/其次/最后」这类套话；用具体的小标题和卡片代替分段。
- 结论先行：每一节的第一句就是这一节的结论。

## 5. 红线

**必须做**

- 每节至少一道题（`quiz` 或 `survey`）。
- 全篇至少一章术语速查表。
- 第 0 章必须包含「这是什么 + 怎么用 + 一道分诊题」。
- 交付前跑 `validate.js`，**错误必须为零**；提示（warning）要么修掉、要么能说出为什么保留。

**不要做**

- **不要在面向「作业 / 考试 / 竞赛」的内容里直接给出可以交差的成品答案或完整代码。** 给思路、给骨架、给参数、给坑，把动手留给读者。这是这类材料最重要的伦理边界。
  - 例外：与考核无关的纯工具性内容（如「怎么装环境」）可以给完整步骤。
- 不要把同一段话在多个章节重复三遍。
- 不要为了凑篇幅拆节。一节讲透一件事，比三节各讲三分之一好。
- 不要写 `index.html`——它是构建产物。
- 不要在 `content.js` 里 `require` 任何东西，它必须能被浏览器直接执行。

## 6. 素材来源的三条路

| 情况 | 做法 |
|---|---|
| **用户给了文件**（PDF / 文档 / 网页） | ① PDF 走 `tools/pdf2text.ps1` 提成文本，通读全文；② 逐条核对事实与样例；③ 需要验证的推导实际跑一遍程序。**不要只读摘要就动笔。** |
| **用户只给了笼统主题** | 自己搜集资料、把知识体系拆成「概念章 → 正课章 → 速查表」，并按 §4.1 为每个术语准备比喻。**信息不足时先问一次关键问题**（面向谁、要多深、有没有指定素材），不要瞎猜。 |
| **用户给了半成品** | 读它的 `content.js`，按同一 schema 续写；先跑一次 `validate.js` 看现有内容有什么问题。 |

## 7. 交付前的验收清单

```
[ ] node learning-pages/tools/validate.js <目录>   → 错误 0 条，提示已处理或已解释
[ ] 全篇搜一遍「首先」「其次」「众所周知」「显然」 → 清掉
[ ] 每个专业名词第一次出现的地方，都有术语卡
[ ] 每个 quiz 的每个错误选项，都是真实会犯的错
[ ] 样例/数字/判定条件，都实际算过
[ ] 开头一章有分诊题，结尾一章有术语速查表和下一步
[ ] storageKey 的版本号是否需要 +1（内容大改过就要）
[ ] Start-Process <目录>\index.html  实际打开看一眼
[ ] 最终回复里说明：产出了什么、验证了什么、哪里有不确定
```

## 8. HTML 片段速查

```html
<!-- 术语卡 -->
<div class="callout c-term"><span class="lb">术语卡 · 名字</span>
比喻。然后一句话定义。</div>

<!-- 划重点 / 小心坑 / 小技巧 / 动手任务 -->
<div class="callout c-key"><span class="lb">划重点</span>…</div>
<div class="callout c-warn"><span class="lb">小心坑</span>…</div>
<div class="callout c-tip"><span class="lb">小技巧</span>…</div>
<div class="callout c-task"><span class="lb">动手任务</span>…</div>

<!-- 代码块（注意 &lt; &gt;） -->
<pre><code><span class="cm">// 注释</span>
if (now - last &gt;= 5) { <span class="ok">正确</span> }
<span class="no">HAL_Delay(500);   // 错误</span>
<span class="hl">关键行</span></code></pre>

<!-- 表格 -->
<table>
  <tr><th style="width:130px">列一</th><th>列二</th></tr>
  <tr><td>内容</td><td>内容</td></tr>
</table>

<!-- 术语速查表 -->
<div class="callout c-term"><span class="lb">术语速查表</span>
<div class="term">
  <b>术语</b><span>一句话解释。</span>
</div></div>
```

题目对象直接写在 `steps` 里，见 §2.1；
最常见的一节长这样：

```js
{
  id:'c1-2', ch:'第 1 章 · 基础概念', tag:'核心',
  title:'变量：贴了标签的盒子',
  body:`
  <p><b>一句话大意：</b>…</p>
  <p>…</p>
  <div class="callout c-term"><span class="lb">术语卡 · 变量</span>…</div>
  `,
  q:{ type:'quiz', text:'…',
    opts:[
      {label:'正确答案', desc:'…', correct:true, why:'…'},
      {label:'常见误解', desc:'…', why:'…'},
      {label:'似是而非', desc:'…', why:'…'}
    ],
    summary:'…' }
}
```
